Rust provides first-class support for inline assembly via three macros: [`asm!`](https://doc.rust-lang.org/core/arch/macro.asm.html), [`naked_asm!`](https://doc.rust-lang.org/core/arch/macro.naked_asm.html), and [`global_asm!`](https://doc.rust-lang.org/core/arch/macro.global_asm.html). Inline assembly allows you to embed handwritten assembly language directly into the assembly output generated by the compiler. This is useful for performance-critical sections, hardware interaction, special CPU instructions, and low-level systems programming tasks that are not expressible in safe Rust.

<Warning>
Inline assembly is an **unsafe** operation. Using `asm!` requires an `unsafe` block. You must uphold strict rules about register usage, memory access, and control flow or the program has undefined behavior.
</Warning>

## Supported Architectures

Inline assembly support is stable on the following architectures:

- x86 and x86-64
- ARM
- AArch64 and Arm64EC
- RISC-V
- LoongArch
- s390x
- PowerPC and PowerPC64

The compiler will emit an error if an assembly macro is used on an unsupported target.

## A Complete Example

```rust
#[cfg(target_arch = "x86_64")]
fn multiply_by_six(x: u64) -> u64 {
    use std::arch::asm;
    let mut result = x;
    unsafe {
        asm!(
            "mov {tmp}, {x}",   // tmp = x
            "shl {tmp}, 1",     // tmp = x * 2
            "shl {x}, 2",       // x   = x * 4
            "add {x}, {tmp}",   // x   = x * 4 + x * 2 = x * 6
            x = inout(reg) result,
            tmp = out(reg) _,
        );
    }
    result
}

#[cfg(target_arch = "x86_64")]
fn main() {
    assert_eq!(multiply_by_six(4), 24);
}

#[cfg(not(target_arch = "x86_64"))]
fn main() {}
```

## Scopes

Inline assembly can be used in three ways:

### `asm!` — Function-scope assembly

Assembly code is emitted within a function, integrated with the compiler's generated code. Must obey strict rules to avoid undefined behavior.

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn example() {
    core::arch::asm!("/* {} */", in(reg) 0);
}
```

### `naked_asm!` — Naked function assembly

Used inside `#[unsafe(naked)]` functions only. The assembly constitutes the **entire** function body — the compiler emits no prologue, epilogue, or additional instructions.

### `global_asm!` — File-scope assembly

Assembly code is emitted in the global scope, outside any function. Useful for writing entire functions in assembly or for data sections:

```rust
fn main() {}
#[cfg(target_arch = "x86_64")]
core::arch::global_asm!("/* {} */", const 0);
```

## Template String Syntax

The assembler template uses the same syntax as Rust's format strings: placeholders are specified with curly braces `{}`.

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn template_examples() {
    let x: i64;
    let y: i64;
    let z: i64;

    // Positional (by order):
    core::arch::asm!("mov {}, {}", out(reg) x, in(reg) 5i64);

    // Positional (by index):
    core::arch::asm!("mov {0}, {1}", out(reg) y, in(reg) 5i64);

    // Named:
    core::arch::asm!("mov {out}, {in}", out = out(reg) z, in = in(reg) 5i64);
}
```

Multiple template strings are treated as if concatenated with a newline between them:

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn multi_string() {
    let x: i64;
    let y: i64;
    core::arch::asm!(
        "mov eax, 5",
        "mov ecx, eax",
        out("rax") x,
        out("rcx") y,
    );
}
```

<Note>
Unlike Rust's `format!` macro, implicit named arguments (e.g., referring to a local variable `x` directly as `{x}`) are **not supported** in `asm!`. You must always provide an explicit operand.
</Note>

## Operand Types

Operands specify how Rust values are passed into and received from assembly code.

### `in` — Input operands

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn demo() {
    core::arch::asm!("/* {} */", in(reg) 5i64);
}
```

- The register contains the value of the expression at the start of the assembly block.
- The register must contain the same value on exit (unless a matching `lateout` is allocated to the same register).

### `out` — Output operands

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn demo() {
    let x: i64;
    core::arch::asm!("/* {} */", out(reg) x);
}
```

- The register has an **undefined** value at the start of the assembly.
- The expression (which must be a place expression) receives the register's value at the end.
- Use `_` to discard the output (acts as a clobber).

### `lateout` — Late output operands

Identical to `out`, but the register allocator can reuse a register allocated to an `in`. Only safe to write after all inputs are read.

### `inout` — Read-modify-write operands

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn demo() {
    let mut x: i64 = 4;
    core::arch::asm!("inc {}", inout(reg) x);
    assert_eq!(x, 5);
}
```

- The register is initialized from the expression value.
- The expression receives the register's final value.
- Can use the `=>` form to use separate in/out expressions: `inout(reg) input => output`.

### `inlateout` — Late read-modify-write operands

Same as `inout`, but the register allocator can reuse an `in` register. Only safe to write after all inputs are read.

### `const` — Constant values

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn demo() {
    const SHIFT: u8 = 3;
    let mut x: i64 = 1;
    core::arch::asm!("shl {}, {}", inout(reg) x, const SHIFT);
}
```

- The expression must be an integer constant. Its value is substituted as a literal string into the template.
- Defaults to type `i32` if not otherwise constrained.

### `sym` — Symbol references

```rust
#[cfg(target_arch = "x86_64")]
extern "C" fn foo() {
    println!("called via asm");
}

#[cfg(target_arch = "x86_64")]
unsafe fn demo() {
    core::arch::asm!("call {}", sym foo, clobber_abi("C"));
}
```

- `<path>` must refer to a `fn` or `static`. A mangled symbol name is substituted into the template.

### `label` — Branch target blocks

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn demo() {
    core::arch::asm!("jmp {}", label {
        println!("jumped here from inline assembly");
    });
}
```

- The address of the block is substituted. The block starts a new safety context.
- Only `in`, `out`, `lateout`, `inout`, `inlateout`, `const`, and `sym` are valid for `asm!`. `naked_asm!` and `global_asm!` only support `sym` and `const`.

## Register Operands

Input and output operands are specified as either a **register class** (identifier) or an **explicit register** (string literal):

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn demo() {
    let y: i64;
    core::arch::asm!("mov eax, {:e}", in(reg) 5i32, lateout("eax") y);
}
```

Commonly used register classes:

| Architecture | Class | Example registers |
|-------------|-------|-----------------|
| x86/x86-64 | `reg` | `ax`, `bx`, `cx`, `dx`, `si`, `di`, `r[8-15]` |
| x86 | `xmm_reg` | `xmm[0-15]` |
| AArch64 | `reg` | `x[0-30]` |
| AArch64 | `vreg` | `v[0-31]` |
| ARM | `reg` | `r[0-12]`, `r14` |
| RISC-V | `reg` | `x1`, `x[5-7]`, `x[9-31]` |

<Note>
Some registers are reserved and cannot be used for input or output: the stack pointer (`sp`), the frame pointer (`bp`/`fp`/`x29` depending on architecture), and several platform-reserved registers. Attempting to use them produces a compile-time error.
</Note>

## ABI Clobbers

The `clobber_abi` keyword automatically adds clobbers for all registers that are not preserved across a call with a particular calling convention:

```rust
#[cfg(target_arch = "x86_64")]
extern "C" fn foo() -> i32 { 0 }

#[cfg(target_arch = "x86_64")]
unsafe fn demo() {
    let z: i32;
    core::arch::asm!("call {}", sym foo, out("rax") z, clobber_abi("C"));
    assert_eq!(z, 0);
}
```

Supported ABI names for `clobber_abi` include `"C"`, `"system"`, `"efiapi"`, `"win64"`, `"sysv64"`, `"aapcs"`, and others depending on the target.

## Options

Options are specified via `options(...)` and control compiler assumptions about the assembly block.

| Option | Meaning |
|--------|---------|
| `pure` | No side effects; outputs depend only on inputs. Allows the compiler to hoist or eliminate. Must be combined with `nomem` or `readonly`. |
| `nomem` | Does not read from or write to memory outside the assembly block. |
| `readonly` | Does not write to any memory outside the assembly block (may read). |
| `preserves_flags` | Does not modify the flags register. |
| `noreturn` | Does not fall through. Undefined behavior if it does. |
| `nostack` | Does not push data to the stack or write to the stack red-zone. |
| `att_syntax` | Use AT&T syntax instead of Intel syntax (x86 only). |
| `raw` | Treat the template as a raw assembly string with no `{}`/`}` handling. |

```rust
#[cfg(target_arch = "x86_64")]
unsafe fn pure_example() {
    let x: i32 = 0;
    let z: i32;
    core::arch::asm!("inc {}", inout(reg) x => z, options(pure, nomem));
}
```

<Warning>
`nomem` and `readonly` are mutually exclusive. Specifying both is a compile-time error. Specifying `pure` without either is also a compile-time error.
</Warning>

## `global_asm!` for File-Scope Assembly

`global_asm!` emits assembly at the global scope. It can only use `sym` and `const` operands. It is useful for:

- Writing entire functions in assembly
- Embedding data sections
- Platform-specific runtime stubs

```rust
fn foo() {}

#[cfg(target_arch = "x86_64")]
core::arch::global_asm!("/* {} {} */", const 0, sym foo);
```

## Rules for Safe Inline Assembly

To avoid undefined behavior, the following rules must be followed when using `asm!`:

1. Registers not specified as inputs contain **undefined values** on entry.
2. Registers not specified as outputs must have the **same value** on exit as on entry.
3. **Unwinding** out of assembly code is undefined behavior.
4. The set of memory locations accessible is the same as for an FFI function.
5. The compiler cannot assume the instructions will literally be those in the source (runtime patching is allowed).
6. Unless `nostack` is set, assembly may use stack space below the stack pointer; the stack pointer must be restored before exiting.
7. If `noreturn` is set, falling through the end is undefined behavior.
8. If `pure` is set, side effects other than direct outputs are undefined behavior.
9. On x86, the direction flag (DF) must be clear on entry and exit.
10. On x86, the x87 FP register stack must be unchanged unless all `st([0-7])` registers are clobbered.
