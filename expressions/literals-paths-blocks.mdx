Rust's most fundamental expressions are the ones that produce values directly from source-code tokens (literals), refer to named things in scope (paths), and group sequences of statements into a single evaluatable unit (blocks). Understanding these three forms is essential because every other expression builds on them.

## Literal Expressions

A *literal expression* consists of a single token that directly and immediately denotes the value it evaluates to, rather than referring to it by name or some evaluation rule. Literals are a form of constant expression, so they are evaluated primarily at compile time.

```rust
"hello";   // string type
'5';       // character type
5;         // integer type
```

### Character Literals

A character literal expression consists of a single `CHAR_LITERAL` token. Its type is the primitive `char` type.

```rust
'R';           // R
'\'';          // '
'\x52';        // R
'\u{00E6}';    // LATIN SMALL LETTER AE (U+00E6)
```

### String Literals

A string literal expression consists of a `STRING_LITERAL` or `RAW_STRING_LITERAL` token. Its type is `&'static str` — a shared reference with a `static` lifetime to the primitive `str` type.

```rust
"foo"; r"foo";                  // foo
"\"foo\""; r#""foo""#;          // "foo"
"foo #\"# bar";
r##"foo #"# bar"##;             // foo #"# bar
"\x52"; "R"; r"R";              // R
"\\x52"; r"\x52";               // \x52
```

Raw string literals (`r"..."` or `r#"..."#`) treat the content literally — no escape processing occurs.

### Byte Literals

A byte literal expression has type `u8`. Byte string literals have type `&'static [u8; N]`.

```rust
b'R';       // 82
b'\'';      // 39
b'\x52';    // 82
b'\xA0';    // 160

b"foo"; br"foo";                // foo
b"\x52"; b"R"; br"R";          // R
```

### C String Literals

A C string literal expression has type `&'static core::ffi::CStr`. The represented bytes are followed by a null byte in memory.

```rust
c"foo"; cr"foo";                // foo
c"æ";                           // LATIN SMALL LETTER AE (U+00E6)
c"\u{00E6}";                    // LATIN SMALL LETTER AE (U+00E6)
```

### Integer Literals

An integer literal expression consists of a single `INTEGER_LITERAL` token. If the token has a suffix (e.g. `u8`, `i32`, `usize`), the expression has that type. Without a suffix, the type is inferred from context or defaults to `i32`.

```rust
123;                // type i32
123i32;             // type i32
123u32;             // type u32
123_u32;            // type u32
let a: u64 = 123;   // type u64

0xff;               // type i32 (hexadecimal)
0xff_u8;            // type u8

0o70;               // type i32 (octal)
0o70_i16;           // type i16

0b1111_1111_1001_0000;     // type i32 (binary)
0b1111_1111_1001_0000i64;  // type i64

0usize;             // type usize
```

<Note>
  `-1i8` is an application of the negation operator to the literal `1i8`, not a single integer literal expression. The most negative value of a signed type must be written as e.g. `i8::MIN` or via negation of a literal.
</Note>

### Floating-Point Literals

A floating-point literal expression has type `f32` or `f64` determined by suffix or type inference (defaulting to `f64`).

```rust
123.0f64;        // type f64
0.1f64;          // type f64
0.1f32;          // type f32
12E+99_f64;      // type f64
5f32;            // type f32
let x: f64 = 2.; // type f64
```

<Note>
  `inf` and `NaN` are not literal tokens. Use `f32::INFINITY`, `f64::INFINITY`, `f32::NAN`, and `f64::NAN` instead.
</Note>

### Boolean Literals

A boolean literal expression is either the keyword `true` or `false`, with type `bool`.

## Path Expressions

A *path expression* is a path used in an expression context. It denotes either a local variable or an item (function, constant, enum variant, type, etc.).

Path expressions that resolve to local or static variables are **place expressions**; all other paths are **value expressions**.

```rust
mod globals {
    pub static STATIC_VAR: i32 = 5;
    pub static mut STATIC_MUT_VAR: i32 = 7;
}
let local_var = 3;

local_var;
globals::STATIC_VAR;
unsafe { globals::STATIC_MUT_VAR };
let some_constructor = Some::<i32>;
let push_integer = Vec::<i32>::push;
let slice_reverse = <[i32]>::reverse;
```

<Warning>
  Using a `static mut` variable requires an `unsafe` block. Mutable statics can introduce data races.
</Warning>

Path expressions can reference:
- **Local variables** — place expressions
- **Static variables** — place expressions
- **Functions** — value expressions producing a function item
- **Enum variant constructors** — value expressions
- **Constants and associated constants** — evaluated the same way as `const` blocks

## Block Expressions

A *block expression* (or *block*) is both a control flow expression and an anonymous namespace scope for items and variable declarations. It sequentially executes its component statements, then evaluates its final optional expression.

```
{
    InnerAttribute*
    Statement*
    ExpressionWithoutBlock?   // optional "tail" / final operand
}
```

### Block Values

- When a block contains a **final operand** (a trailing expression without a semicolon), the block has the type and value of that final operand.
- When a block has **no final operand** and does not diverge, the block has unit type `()`.
- When a block has **no final operand** and diverges, the block has the never type `!`.

```rust
let x: u8 = { 0u8 };       // final operand is 0u8
assert_eq!(x, 0);

let y: () = {};             // no final operand → unit type
assert_eq!(y, ());

let z: () = { 0u8; };      // semicolon discards value → unit type
assert_eq!(z, ());
```

### `unsafe` Blocks

A block prefixed with `unsafe` permits unsafe operations within it.

```rust
unsafe {
    let b = [13u8, 17u8];
    let a = &b[0] as *const u8;
    assert_eq!(*a, 13);
    assert_eq!(*a.offset(1), 17);
}

unsafe fn an_unsafe_fn() -> i32 { 10 }
let a = unsafe { an_unsafe_fn() };
```

### `async` Blocks

An *async block* is a block expression that evaluates to a future (a type implementing `std::future::Future`). The final expression of the block, if present, determines the result value of the future. The actual data format of the generated type is unspecified.

```rust
async fn example() -> i32 {
    let fut = async {
        42
    };
    fut.await
}
```

Async blocks capture their environment using the same capture modes as closures:
- `async { .. }` — capture mode for each variable is inferred from the block's content.
- `async move { .. }` — moves all referenced variables into the resulting future.

Because async blocks construct a future, they define an **async context** in which `await` expressions are legal. The `?` and `return` operators inside an async block affect the *output of the future*, not the enclosing function.

```rust,compile_fail
loop {
    async move {
        break; // error: `break` inside of an `async` block
    }
}
```

<Note>
  Async blocks are only available beginning with Rust 2018.
</Note>

### `const` Blocks

A *const block* evaluates its body at **compile time** instead of at runtime. It supports type inference (unlike named constant items) and can reference generic parameters in scope.

```rust
fn foo<T>() -> usize {
    const { std::mem::size_of::<T>() + 1 }
}
```

If the const block expression is executed at runtime, the constant is guaranteed to have been evaluated:

```rust
fn foo<T>() -> usize {
    // This assertion is evaluated at compile-time.
    const { assert!(std::mem::size_of::<T>() > 0); }
    42
}
```

### Labeled Block Expressions

Labeled block expressions are like ordinary blocks but allow `break` expressions (with the label) to exit early and produce a value. Unlike loops, `break` within a labeled block *must* use the label.

```rust
fn do_thing() {}
fn condition_not_met() -> bool { true }
fn do_next_thing() {}
fn do_last_thing() {}

let result = 'block: {
    do_thing();
    if condition_not_met() {
        break 'block 1;
    }
    do_next_thing();
    if condition_not_met() {
        break 'block 2;
    }
    do_last_thing();
    3
};
```

### Attributes on Block Expressions

Inner attributes are allowed directly after the opening brace in: function and method bodies, loop bodies, block expressions used as statements, block expressions as elements of arrays/tuples/calls/structs, and a block expression as the tail expression of another block.

```rust
fn is_unix_platform() -> bool {
    #[cfg(unix)] { true }
    #[cfg(not(unix))] { false }
}
```
